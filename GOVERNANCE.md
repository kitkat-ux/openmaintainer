# Governance

OpenMaintainer is maintained by the repository owner and active volunteer maintainers. Maintainers review code, protect users, manage releases, and keep CI and documentation healthy.

Changes are proposed through pull requests. Maintainers seek consensus, require passing tests and security review for sensitive changes, and make the final decision when consensus is not possible. Breaking API or configuration changes should include a Changesets entry and migration notes.

The repository owner may add maintainers based on sustained, constructive contributions and shared project values. Maintainers should disclose conflicts of interest and recuse themselves when appropriate. Disputes should first be resolved respectfully with the maintainers; the repository owner makes the final project decision.

Releases are prepared with Changesets and are intentionally explicit. No package or GitHub release is published merely because code was merged.
